<h2>专线接入和家宽接入，配置上有三处不同</h2>
<p>家宽通常是拨号或自动获取，地址可能变；专线通常是「给你固定地址、掩码、网关」，配置时直接填。</p>
<p>另外两处不同：专线往往允许对外提供服务，所以端口设置更重要；专线可能有多个可用地址，需要决定怎么分。</p>

<h2>第一步：确认接入参数</h2>
<p>要拿到四项：可用地址与掩码、网关地址、是否需要 VLAN 标记、以及 DNS 建议值。前两项必须准确，后两项视运营商要求。</p>
<p>四项里最容易出错的是掩码。填错会导致「能 ping 通网关但出不去」，或者「地址段内的邻居都不可达」。拿到参数后逐位核对。</p>

<h2>第二步：配 WAN 口</h2>
<p>WAN 口设成静态地址，填入地址、掩码、网关。如果运营商要求 VLAN，需要同时在 WAN 上标记。</p>
<p>MTU 先用默认，出现「能打开网页但部分服务连不上」时再调小。跨境链路常需要更小的 MTU，这一点在专线上更常见。</p>

<h2>第三步：配地址与路由</h2>
<p>如果有多个可用地址，可以把它们都配到 WAN 口，或分配到内网设备。配完之后检查路由表：默认路由指向网关，每个额外地址有对应的直连路由。</p>
<p>多地址场景里最常见的错误是「地址加了但没路由」，表现是该地址完全不可用。加完立刻逐地址测一次。</p>

<h2>第四步：端口设置</h2>
<p>专线常需要对外提供服务，所以要配端口映射。每个映射记清四项：公网地址、公网端口、内网地址、内网端口。</p>
<p>建议只映射必要的端口，并且限制来源。全端口映射等于把设备完全暴露，风险很高。</p>

<h2>第五步：验证</h2>
<p>四项验证：地址能出网、每个额外地址也能出网、外部能按预期访问到对应服务、断开重连后配置仍然生效。</p>
<p>第四项常被省略。有些配置在重启后不保留，验证一次能提前发现。</p>

<h2>三个常见问题</h2>
<p>一是「地址对了但打不开网页」。先查 DNS，再查 MTU。二是「外部访问不到服务」。查映射、查防火墙、查运营商是否封端口。</p>
<p>三是「重启后配置丢失」。查是否保存了配置、是否用了非持久化的方式。这三个问题的排查顺序，比反复重启有效。</p>

<h2>安全底线</h2>
<p>三条：改默认管理口令、限制管理界面的访问来源、关闭不用的服务（远程管理、通用即插即用）。</p>
<p>专线地址是固定的，暴露在公网上会被持续扫描。三条都做到，能挡掉绝大部分自动化尝试。</p>

<h2>先把「谁能进来」定下来，再谈端口</h2>
<p>端口设置的默认思路是「需要就开」，更稳的思路是先定访问来源：这个端口只给自己用，还是给特定合作方用。定完之后，来源限制往往能砍掉大部分开放需求。</p>
<p>这一层想清楚了，后面端口开得少、规则也简单，排错时一眼能看完。反过来先开一堆端口再收，既费时间，也容易留下忘了关的。</p>
<p>还有一件事值得顺手做：把当前配置导出一份备份。设备故障或误操作之后，能直接恢复比重配一遍快得多，也更不容易漏掉某一项。</p>
<h2>常见问答</h2>
<h3>专线一定要静态配置吗？</h3>
<p><strong>答：</strong>多数是。运营商给固定地址，直接填即可。</p>
<h3>多个地址怎么分给内网设备？</h3>
<p><strong>答：</strong>一对一映射或地址下发。按是否需要出站独立来选。</p>
<h3>端口映射后外网还是连不上？</h3>
<p><strong>答：</strong>查防火墙、查运营商是否封端口、查目标服务是否在跑。</p>
<h3>需要开全部端口吗？</h3>
<p><strong>答：</strong>不需要。只开必要的，并限制来源。</p>
